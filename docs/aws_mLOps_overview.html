Bức Tranh Tổng Thể: AI Pulmonary Diagnostic Suite trên AWS (MLOps)

1. Mục tiêu và Định hướng

Chuyển đổi dự án chẩn đoán bệnh lý phổi hiện tại (dùng file cục bộ .keras, .tflite) thành một hệ thống AI cấp độ doanh nghiệp, hoạt động hoàn toàn trên môi trường Cloud (Cloud-native) của AWS.

Lợi ích cốt lõi: Quản lý tập trung các phiên bản mô hình, tự động hóa quy trình huấn luyện với dữ liệu X-Quang mới, phục vụ dự đoán thời gian thực (Real-time Inference) và theo dõi độ chính xác (Data Drift).

2. Sơ đồ Kiến trúc Đề xuất (Cấp độ cao)

  • Bước 1 (Lưu trữ): Dữ liệu ảnh X-Quang được lưu bảo mật trên Amazon S3.
  • Bước 2 (Huấn luyện & Đóng gói): Amazon SageMaker đọc dữ liệu từ S3, huấn luyện và chuyển đổi model (Keras/TFLite), lưu bản mới nhất vào SageMaker Model Registry.
  • Bước 3 (Phục vụ Dự đoán): Backend không tải file trực tiếp nữa, mà gửi link ảnh X-Quang (hoặc Base64) qua Amazon API Gateway -> AWS Lambda -> gọi đến SageMaker Endpoint đang chạy model.
  • Bước 4 (Giám sát): SageMaker Model Monitor giám sát chất lượng; CloudWatch ghi log lưu lượng sử dụng từ ứng dụng app.py.

3. Lộ trình Triển khai 8 Tuần

Giai đoạn Công việc đối với dự án Pulmonary Diagnostic Dịch vụ AWS sử dụng
Tuần 1-3
Thiết lập Cơ sở & Chuyển dịch Dữ liệu
- Tạo Bucket lưu trữ ảnh X-Quang.
- Upload bộ script Python (`app.py`, script training) lên SageMaker Studio.
- Viết lại code huấn luyện để đọc dữ liệu Cloud thay vì đọc từ ổ cứng.
 Amazon S3, IAM, SageMaker Studio, SageMaker Training Jobs
Tuần 4
Tối ưu hóa Mô hình (HPO)
- Thiết lập tự động dò tìm các tham số (Hyperparameters) lõi của thuật toán nhận diện phổi để tăng độ chính xác thay vì fine-tune thủ công.
 SageMaker Automatic Model Tuning, SageMaker Experiments
Tuần 5
Kho lưu trữ Phiên bản Mô hình
- Đưa pneumonia_model_finetuned.keras vào Model Registry.
- Định nghĩa các thẻ đánh giá (Staging/Production) để biết model nào đang sẵn sàng sử dụng.
 SageMaker Model Registry
Tuần 6
Triển khai API Dự đoán
- Deploy model (Version: Production) lên 1 Endpoint bảo mật.
- Viết một hàm trung gian kết nối `app.py` với Endpoint đó thông qua môi trường HTTP REST.
 SageMaker Real-time Endpoint, AWS Lambda, API Gateway
Tuần 7
Giám sát Y tế (Data Drift)
- Phát hiện độ phân giải/màu sắc của các ảnh X-Quang mới có khác với dữ liệu huấn luyện hay không (Data Drift). Gửi cảnh báo để tái huấn luyện.
 SageMaker Model Monitor, Amazon CloudWatch
Tuần 8
Tự động hóa toàn phần (CI/CD/CT)
- Tổ hợp toàn bộ Cấu hình -> Huấn luyện -> Đánh giá -> Triển khai thành một luồng (Pipeline) duy nhất. Cứ có rổ X-Quang mới là mô hình tự học lại.
 SageMaker Pipelines

4. Định hướng cho TFLite (IoT / Edge Devices)

Bạn đã có sẵn pneumonia_model.tflite. Trong môi trường AWS, chúng ta có thể sử dụng AWS IoT Greengrass kết hợp SageMaker Neo để đẩy file tflite này trực tiếp xuống các máy siêu âm/X-quang di động tại các trạm biên (Edge), giúp chẩn đoán ngay khi không có kết nối mạng (hoạt động offline).

AI Pulmonary Diagnostic Suite
Tổng Quan Dự Án & Kế Hoạch Triển Khai MLOps trên AWS

1. Giới thiệu Project

AI Pulmonary Diagnostic Suite là một hệ thống hỗ trợ chẩn đoán hình ảnh y tế, được xây dựng nhằm phát hiện bệnh viêm phổi (pneumonia) từ ảnh X-Quang ngực. Hệ thống hướng đến việc trở thành một công cụ hỗ trợ lâm sàng đáng tin cậy, có khả năng giải thích kết quả (explainable), giúp bác sĩ và nhân viên y tế đưa ra quyết định nhanh và chính xác hơn.

Điểm nổi bật của dự án là kiến trúc "Dual-Engine" — kết hợp giữa một mô hình nhẹ, tốc độ cao (TFLite) để sàng lọc hàng loạt, và một mô hình đầy đủ (Keras) để sinh bản đồ nhiệt Grad-CAM giải thích vùng tổn thương trên phổi. Toàn bộ hệ thống hiện được đóng gói trong một ứng dụng web triển khai bằng Streamlit.

Kiến trúc & Công nghệ hiện tại

  • Mô hình nền (Base Model): DenseNet121, áp dụng kỹ thuật Transfer Learning.
  • Dữ liệu huấn luyện: Hơn 5.800 ảnh X-Quang, có sử dụng data augmentation để tăng độ tổng quát hóa.
  • Chỉ số hiệu năng chính: Recall đạt 92%, được tối ưu để giảm thiểu tối đa các trường hợp âm tính giả (bỏ sót ca bệnh).
  • Giao diện & triển khai: Web app bằng Streamlit, kèm các tiện ích hỗ trợ đọc ảnh X-Quang trực tiếp trên trình duyệt.
  • Xuất dữ liệu: Hỗ trợ xuất kết quả chẩn đoán hàng loạt sang Excel (.xlsx) hoặc văn bản lâm sàng (.txt).

1.1. Những gì đã làm được

  • Mô hình Xây dựng và huấn luyện thành công mô hình baseline dựa trên DenseNet121, đạt Recall 92% — phù hợp với mục tiêu y tế là ưu tiên không bỏ sót ca dương tính.
  • XAI Tích hợp Grad-CAM để sinh bản đồ nhiệt trực quan, giúp minh bạch hóa quyết định của mô hình — yếu tố quan trọng để xây dựng niềm tin trong môi trường y tế.
  • Tối ưu hóa Chuyển đổi (convert) mô hình sang TFLite, giảm độ trễ suy luận, cho phép xử lý đồng thời tới 10 ảnh trong một lượt (batch).
  • Sản phẩm Triển khai end-to-end ứng dụng web hoàn chỉnh bằng Streamlit, có thể truy cập trực tuyến (live demo).
  • UX Thiết kế luồng làm việc thực tế: tự động phân loại ca bệnh theo mức độ (Critical / Review Required / Cleared), có cơ chế con người xác nhận lại (human-in-the-loop), và công cụ chỉnh sáng ảnh X-Quang ngay trên trình duyệt.
  • Xuất dữ liệu Hỗ trợ xuất báo cáo hàng loạt ra Excel hoặc file văn bản để lưu hồ sơ.

1.2. Những gì chưa làm được / còn hạn chế

  • Hạ tầng Hệ thống hiện vẫn chạy hoàn toàn dựa trên file mô hình cục bộ (.keras, .tflite) lưu trực tiếp trong source code, chưa có cơ chế quản lý phiên bản mô hình tập trung.
  • Bảo mật Chưa có cơ chế xác thực người dùng (authentication), điều cần thiết với một ứng dụng có liên quan tới dữ liệu y tế.
  • Triển khai Ứng dụng chưa được đóng gói bằng Docker — gây khó khăn cho việc nhân bản môi trường hoặc triển khai ở quy mô lớn hơn.
  • Vận hành (MLOps) Chưa có pipeline huấn luyện lại tự động khi có dữ liệu X-Quang mới; mọi việc cập nhật mô hình hiện tại đều là thủ công.
  • Giám sát Chưa có hệ thống theo dõi data drift hoặc giám sát chất lượng dự đoán theo thời gian thực sau khi mô hình được đưa vào sử dụng thực tế.
  • Quy mô Kiến trúc hiện tại (Streamlit + file cục bộ) phù hợp cho demo/PoC, nhưng chưa đáp ứng được yêu cầu vận hành ổn định ở cấp độ doanh nghiệp (enterprise-grade), với khả năng mở rộng và phục vụ nhiều người dùng đồng thời.

Kế Hoạch Triển Khai: Machine Learning End-to-End trên AWS với SageMaker

(Áp dụng theo nội dung Đề tài 5)

1. Mục tiêu và Định hướng

Xây dựng và triển khai một hệ thống Machine Learning end-to-end hoàn chỉnh trên nền tảng AWS, sử dụng Amazon SageMaker làm trung tâm cho toàn bộ vòng đời mô hình: từ xử lý dữ liệu, huấn luyện, tối ưu hóa, đăng ký phiên bản, triển khai phục vụ dự đoán thời gian thực, đến giám sát và tự động hóa.

Công nghệ sử dụng: Python, Amazon SageMaker, Scikit-learn / XGBoost / PyTorch, Amazon S3, AWS Lambda, Amazon API Gateway, Amazon CloudWatch.

2. Lộ trình Triển khai 8 Tuần

Giai đoạn Nội dung công việc Dịch vụ AWS sử dụng
Tuần 1-3
Tìm hiểu & Chuẩn bị Dữ liệu
- Tìm hiểu tổng quan về ML workflow và hệ sinh thái AWS ML.
- Cấu hình môi trường làm việc: thiết lập IAM, tạo bucket S3, khởi tạo SageMaker Studio.
- Chuẩn bị và xử lý dữ liệu (data preprocessing, feature engineering) bằng SageMaker Processing Jobs.
- Huấn luyện mô hình (Training Jobs) trên SageMaker, thử nghiệm với các thuật toán built-in hoặc custom training script.
 IAM, Amazon S3, SageMaker Studio, SageMaker Processing Jobs, SageMaker Training Jobs
Tuần 4
Theo dõi Thí nghiệm & Tối ưu hóa (HPO)
- Theo dõi và so sánh các thí nghiệm huấn luyện bằng SageMaker Experiments.
- Tối ưu hóa siêu tham số (hyperparameters) tự động bằng Automatic Model Tuning để cải thiện độ chính xác mô hình.
 SageMaker Experiments, SageMaker Automatic Model Tuning
Tuần 5
Đóng gói & Quản lý Phiên bản Mô hình
- Đóng gói mô hình đã huấn luyện và đăng ký vào SageMaker Model Registry.
- Thiết lập quy trình quản lý phiên bản (model versioning) và gắn nhãn trạng thái (Staging / Production).
 SageMaker Model Registry
Tuần 6
Triển khai API Dự đoán Thời gian thực
- Triển khai mô hình (phiên bản Production) lên SageMaker Endpoint để phục vụ real-time inference.
- Tích hợp Amazon API Gateway và AWS Lambda để mở endpoint dưới dạng REST API cho các hệ thống bên ngoài gọi đến.
 SageMaker Real-time Endpoint, AWS Lambda, Amazon API Gateway
Tuần 7
Giám sát Mô hình & Phát hiện Data Drift
- Thiết lập hệ thống giám sát chất lượng mô hình với SageMaker Model Monitor.
- Cấu hình Amazon CloudWatch để ghi log, theo dõi lưu lượng sử dụng và cảnh báo kịp thời khi phát hiện hiện tượng lệch dữ liệu (data drift).
 SageMaker Model Monitor, Amazon CloudWatch
Tuần 8
Tự động hóa Toàn phần (CI/CD/CT) & Tổng kết
- Tự động hóa toàn bộ quy trình (chuẩn bị dữ liệu → huấn luyện → đánh giá → triển khai) thành một pipeline duy nhất bằng SageMaker Pipelines.
- Tổng hợp kết quả thực hiện, đánh giá hiệu năng tổng thể và hoàn thiện báo cáo cuối kỳ.
 SageMaker Pipelines

3. Liên hệ với Project AI Pulmonary Diagnostic Suite

Lộ trình trên có thể được áp dụng trực tiếp để nâng cấp project hiện tại: dữ liệu X-Quang sẽ được chuyển lên Amazon S3 thay cho lưu trữ cục bộ; quá trình huấn luyện DenseNet121 và chuyển đổi sang TFLite sẽ được thực hiện trên SageMaker Training Jobs; mô hình pneumonia_model_finetuned.keras sẽ được quản lý phiên bản qua SageMaker Model Registry; và việc dự đoán sẽ được phục vụ qua SageMaker Endpoint kết hợp API Gateway / Lambda, thay cho việc ứng dụng app.py tải trực tiếp file mô hình như hiện nay. Đây chính là nền tảng để giải quyết các hạn chế đã nêu ở phần 1.2: quản lý phiên bản mô hình, giám sát data drift, và tự động hóa huấn luyện lại.
